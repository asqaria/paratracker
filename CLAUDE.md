# Skyline — правила проекта для Claude Code

Платформа 3D-визуализации и анализа парапланерных полётов.
Полное ТЗ — в `docs/SPEC.md`. **Перед началом любой задачи прочитай релевантный раздел ТЗ.**

---

## Структура монорепозитория

```
/apps
  api/             Fastify 5: HTTP, auth, SSE. Тонкий слой над пакетами
  worker/          конвейер обработки треков + пул worker_threads
  web/             React 19 + Vite + Tailwind v4 + Zustand + TanStack Query
    src/viewer/    ВЕСЬ код CesiumJS живёт только здесь
  render/          Puppeteer + ffmpeg → MP4 (Фаза 4)
/packages
  core/            домен: типы, ParsedTrack, Zod-схемы DTO, constants.ts
  parsing/         igc.ts, gpx.ts, kml.ts, fit.ts
  analysis/        circles.ts, thermals.ts, glides.ts, wind.ts
  track-format/    writeTrack + readTrack — одна реализация на всех
  db/              Drizzle-схема, миграции, репозитории
/fixtures          эталонные IGC/GPX + expected.json (генерируются tools/)
/tools             make-fixtures.mjs и прочие скрипты
/infra             docker-compose, деплой
/docs/SPEC.md      техническое задание
```

Слои Clean Architecture проходят по пакетам: `core` — домен,
`parsing`/`analysis`/`track-format` — приложение, `db` — инфраструктура.

## Жёсткие правила

### Зависимости между пакетами

- **`packages/core` не зависит ни от чего.** Ни от Fastify, ни от Drizzle,
  ни от Cesium, ни от Node-specific API. Проверяется линтером.
- `parsing`, `analysis`, `track-format` зависят только от `core`.
  Никаких обращений к БД, сети и файловой системе внутри них — только чистые
  функции над данными. Это условие того, чтобы их можно было гонять
  в `worker_threads` и тестировать без окружения.
- `apps/*` зависят от пакетов, но пакеты никогда не зависят от `apps/*`.

### Производительность рантайма

- **CPU-тяжёлое — только в `worker_threads`.** Парсинг, анализ, скоринг,
  упаковка `.track`. Синхронный код дольше ~100 мс в основном потоке
  недопустим: он останавливает и очередь, и SSE-поток статусов.
- Это главный риск выбранного стека. Проверка живая: во время обработки
  4-часового трека `/health` обязан отвечать быстрее 200 мс — вынеси в тест.
- Большие массивы точек — типизированные массивы (`Float64Array`,
  `Int32Array`), не массивы объектов. Передача между потоками — transferable.

### Единицы и время

- **Внутри системы — только СИ:** метры, м/с, секунды, градусы.
  Километры в час, футы, узлы — только на границе UI при форматировании.
- **Внутри системы — только UTC.** Локальное время вычисляется из таймзоны
  места старта и только для отображения.
- Координаты — WGS84, десятичные градусы, `number` (double). Никогда не строки.
- **Высоты — над эллипсоидом WGS84**, а не над геоидом. Любой источник DEM
  с ортометрическими высотами (Copernicus = EGM2008) пересчитывается на
  границе инфраструктурного слоя.
- **Направление ветра — метеорологическое, «откуда дует».** Везде: в БД,
  в API, в UI. Вектор сноса термика конвертируется (+180°) в момент записи.

### Формат `.track`

- Бинарный колоночный формат, спецификация в ТЗ §5.4.
- Одна реализация — `packages/track-format`. Воркер пишет, фронт читает.
- Менять структуру — **только** с инкрементом `version` в заголовке.
- Round-trip тест обязателен, и обязательно **на нечётном `pointCount`**:
  без выравнивания колонок по 8 байт `new Int32Array(buffer, offset, n)`
  бросит `RangeError`, и это всплывёт только на конкретных треках.
- `dt` — `Uint16` в миллисекундах, потолок 65 535 мс. Разрыв больше
  кодируется как `0xFFFF`, фактическая длительность — в таблице разрывов.

### Алгоритмы анализа

- Один алгоритм = один модуль в `packages/analysis` = один тестовый файл.
- **Без теста на файле из `/fixtures` изменение не принимается.**
- Тест пишется ПЕРВЫМ. Эталон — `fixtures/expected.json`: там точные значения,
  сверять на равенство с допуском 1e-9, а не «примерно».
- Никаких магических чисел. Все пороги — в `packages/core/constants.ts`,
  каждый с комментарием, откуда взято значение.
  Плохо:  `if (radius > 15 && radius < 120)`
  Хорошо: `if (radius > THERMAL.minCircleRadiusM && radius < THERMAL.maxCircleRadiusM)`
- Алгоритмы детерминированные: один и тот же вход → один и тот же выход.
- Параметры детекции параметризуются по типу ЛА (параплан / дельтаплан / планер) —
  у них разные радиусы виражей и скорости.

### Парсеры

- Парсер **никогда не бросает исключение на кривой строке.** Пропускает,
  пишет в `warnings`, продолжает. Пустая строка предупреждения не заслуживает,
  неизвестный тип записи — заслуживает.
- Парсер не имеет доступа к сети и файловой системе — только к переданному
  буферу или строке.
- Каждый найденный «сломанный» реальный файл добавляется в `/fixtures`
  вместе с тестом. Fixtures — регрессионный набор, он только растёт.
- Каждый парсер приводит результат к единому `ParsedTrack` из `core` (ТЗ §3.4).

### Фронтенд

- **Импорт `cesium` вне `apps/web/src/viewer/` — ошибка сборки.**
  Настроено в eslint. Остальное приложение работает с абстракциями.
- Cesium грузится через `React.lazy` только на странице просмотрщика.
  MapLibre — так же. Ни тот, ни другой не попадает в начальный чанк.
- Трек рисуется **одним** `Primitive` с per-vertex цветами.
  Создание `Entity` на точку трека запрещено — это убивает FPS.
- Вершинные цвета — через `PolylineGeometry({ colors, colorsPerVertex: true })`
  + `PolylineColorAppearance`. **Не** `ColorGeometryInstanceAttribute` — он задаёт
  один цвет на весь инстанс. Glow — отдельным примитивом под основным.
- `requestRenderMode: true` по умолчанию; непрерывный рендер только на время
  проигрывания и движения камеры.
- Декодирование `.track` — в Web Worker, буфер передаётся как transferable.
- Источники рельефа и подложки — только через `ITerrainProvider` /
  `IImageryProvider`, URL и ключи из конфига. Хардкод адреса тайл-сервера —
  ошибка ревью. Рельеф — Re:Earth Terrain; подложка — Esri World Imagery
  (ключ ArcGIS Location Platform) либо Sentinel-2 cloudless, по §4.4.1 ТЗ.
- **Блок атрибуции на 3D-сцене обязателен**, не скрывается и меняется вместе
  с провайдером: Re:Earth и EOX под CC BY 4.0, Esri требует «Powered by Esri».
  Без атрибуции использование любой из подложек незаконно.
- Ключ ArcGIS — только из конфига и только через серверный прокси либо
  с доменным ограничением на стороне Esri. В бандл фронта ключ не попадает.
- Никаких строк в JSX напрямую — только через i18n (`ru`, `en`).
- Цифры телеметрии — моноширинный шрифт + `font-variant-numeric: tabular-nums`.

### API

- Контракт — Zod-схемы в `packages/core`, из них выводятся типы для обеих сторон.
  Строку БД наружу не отдавать никогда.
- Ошибки — RFC 9457 Problem Details (`application/problem+json`).
- Пагинация — курсорная, не offset.
- Версия в пути: `/api/v1/...`.

### База данных

- Точки трека **не хранятся построчно.** Только: сырой файл в S3 (gzip),
  `.track` в S3, упрощённая геометрия + агрегаты в Postgres. (ТЗ §5.3)
- Каждое изменение схемы — через миграцию Drizzle, вручную SQL в проде не выполняется.
- Геометрия — `geography`, не `geometry` (нужны корректные расстояния на сфере).
  Тип описывается кастомным типом Drizzle; сложные PostGIS-запросы — raw SQL
  в репозиториях `packages/db`, наружу отдаются уже типизированные результаты.
- Статус в `flights` — единственный источник правды по обработке. При старте
  воркер переставляет в очередь всё, застрявшее в `pending` и `parsing`.

## Технологии — что использовать

| Задача | Решение |
|---|---|
| Язык | TypeScript strict, везде, без исключений |
| Монорепо | pnpm workspaces + Turborepo |
| API | Fastify 5 + Zod |
| ORM | Drizzle ORM; PostGIS — кастомный тип + raw SQL |
| БД | PostgreSQL 17 + PostGIS 3.5 |
| Хранилище | S3-совместимое (MinIO локально, R2 в проде) |
| Фоновые задачи | внутрипроцессная очередь + пул `worker_threads` |
| Фронт | React 19, Vite, Tailwind v4, Zustand, TanStack Query |
| 3D | CesiumJS |
| 2D-карты | MapLibre GL JS |
| Графики | uPlot или собственный canvas — **не Recharts** |
| Тесты | Vitest везде; Playwright для e2e |
| XC-скоринг | `igc-xc-score` как обычная зависимость, вызов в worker_thread |
| Логи | pino, структурные, с `flightId` в контексте |

**Не использовать:** Prisma (слабый PostGIS), NestJS на старте (магия и
косвенность не окупаются на этом размере), Recharts и Chart.js для треков
(медленно на 15k точек), moment.js, `any` в публичных сигнатурах.

## Порядок работы

1. Одна задача из плана фазы = одна сессия = один PR. Не смешивать задачи.
2. Для алгоритмов: **сначала тест с ожидаемыми значениями, потом реализация.**
3. Для 3D-задач: в конце приложить скриншот результата — визуальное
   поведение текстом не проверяется.
4. Перед коммитом: `pnpm turbo test lint typecheck` — всё зелёное.
5. Не начинать следующую фазу, пока текущая не задеплоена и не проверена
   на реальных треках.

## Definition of Done

- [ ] Код покрыт тестами (алгоритмы — обязательно на fixtures)
- [ ] Нет магических чисел
- [ ] Нет `any` в экспортируемых сигнатурах
- [ ] CPU-тяжёлое вынесено в worker_threads
- [ ] Строки UI локализованы
- [ ] Единицы СИ внутри, конвертация только в UI
- [ ] Ошибки обрабатываются с понятным пользователю сообщением
- [ ] Для 3D: проверено на встроенной графике, FPS в пределах ТЗ §7.7
- [ ] Логи структурные, с `flightId` в контексте
